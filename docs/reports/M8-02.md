# M8-02 + M8-03: Describe an open trade; «до входу» / «після угоди» links (tier L)

Branch `m8/open-trade-description`, commits `f1cfba5` (backend), `feeb3f3` (frontend), `e6b1d26` (review fix), `77a660b` (backlog notes), `b723667` (test update). Merge `5a05b6a` (range `e0334dd..5a05b6a`). No DB migration.

## What was built
- **Same record from open to closed.** The sync already created the trade row of an open position on the first sync (unique account + MT5 position_id); partial closes and the close update that row. Verified by tests: one record, never a duplicate.
- **Describe an open trade.** «Описати» on Home «Відкриті позиції» and in the Journal trade card (now also for open trades). The Describe screen shows only the pre-entry fields, «до входу» links, text, voice and audio upload. Draft only: «Зберегти» (complete) is hidden, the API answers 409 `open_trade_complete`. After-trade fields and «після угоди» links are rejected while open (422).
- **After-trade fields** are marked in `config/journal_fields.yaml` (`phase: after`): exit reason, «Дотримався плану», emotion after (+ note), mistakes, lesson. «Якість сетапу» stays pre-entry.
- **AI on an open trade** is offered and may fill pre-entry fields only (schema and result filtered; tested with a fake model, no live call).
- **On close:** a trade described while open becomes `draft` (inbox «Чернетки»); undescribed -> `needs_description` as before; without an initial SL -> `needs_sl`, and after the SL is set -> `draft`. Never completed automatically. Missing fields are highlighted when the draft is opened (exit reason, emotion after, …).
- **Sync never overwrites** journal fields, text or links (only the M8-09 prefill of an empty exit reason).
- **Trade closes while its form is open (review HIGH):** the form stays as it was, a notice «Угоду щойно закрито…» appears, and the save sends `form_open`; the server keeps the stored after-trade values and «після угоди» links, so the MT5 exit-reason prefill is not lost.
- **M8-03 links:** links are shown in groups «Графік до входу» (two empty rows by default) and, for a closed trade, «Графік після угоди» (one empty row, «додати» for more). Empty rows are not saved and do not count toward the 10-link limit. Completion needs at least one «до входу» link (rule unchanged).

## Deviations from the PM brief (please confirm)
1. **No «без позначки» migration.** Every stored trade link already has a type the owner chose in the per-row select since M2 (dev DB: 43 «до входу», 32 «після угоди»), so keeping it is not a guess; the completion rule already required a «до входу» link. Relabelling would discard owner data. If the PM still wants it, it is a small migration.
2. **No new status `open_draft`.** An open trade keeps status `open`; "described while open" = `described_at` set. The lifecycle is the PM's: open -> needs_description / draft (never complete automatically; completing stays the owner's save).
