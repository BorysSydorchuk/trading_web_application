## Audit and resulting behavior

The existing stdlib launcher already installed stale/missing dependencies, recovered
Docker, preserved process identity (PID + creation time + command line), distinguished
foreign port holders, recovered its previous checkout's orphan processes and cleaned
its own child trees. Those facilities and existing tests remain authoritative.
API/worker already loaded YAML and logged errors; migration already required pg_dump
for non-test databases. Gaps were TCP-only DB readiness, overly broad Python/Node
versions, no preflight tool/directory checks, no worker readiness signal and no full
archive inspection in the legacy pre-migration path.

- `scripts/dev.py`: exact Python 3.12.x requirement, matching backend pyproject; Node
  engine check derived from installed Vite's `^20.19.0 || >=22.12.0`, npm execution
  and uv execution checks. No new installer/dependency is introduced.
- New backend `python -m app.tools.startup_check`: validates settings/YAML, probes
  DATA_DIR, LOG_DIR, target-scoped BACKUP_DIR and legacy pre-migration backups folder
  using unique disposable files with fsync. Backup-path links fail closed; existing
  DATA_DIR normalization is preserved. Then checks
  actual SQL connectivity/current_database and version availability of pg_dump and
  pg_restore. Local Docker fallback must match the SQL cluster. No dump, restore,
  upgrade, terminal, model download or AI request is part of preflight.
- Preflight runs after dependency/DB recovery and before migration, for both normal
  startup and `--ensure-db`. Config/driver/tool exceptions become fixed actionable
  Ukrainian text without values, URL or traceback. Config loader's raw diagnostic
  logging is suppressed only during this CLI check, then restored.
- `app.tools.migrate`: before a pending non-test upgrade, confirms target and Docker
  cluster when applicable; pg_restore reads TOC and all data blocks while the dump is
  still private `.partial`, then fsync and publication precede upgrade. Verification
  failure blocks upgrade and removes only the new partial. Manual/pre-migration
  retention remains protected. Existing no-pending behavior and `_test` exemption
  remain. Printed migration errors now use the existing credential redactor.
- Worker emits one scoped stdout acknowledgement after scheduler.start; the launcher
  consumes it from that child pipe. The marker is a random per-launch token, not a
  credential or persisted file. Parsing tolerates scheduler output interleaving.
- Readiness now requires a currently healthy API/DB, worker acknowledgement and Vite
  response; a previously healthy DB is rechecked while awaiting the worker. Child
  death or timeout fails startup and runs existing child cleanup. Cleanup skips
  exited PIDs and validates live Windows process identity before tree termination;
  fallback uses the original Popen process handle, never a reused foreign PID.
- No AI/MT5 availability check is added. Optional failures keep existing manual flows
  and visible status/errors. Launcher strings stay in its existing Ukrainian MSG
  table; backend CLI messages are Ukrainian. No frontend UI string changes needed.

## Limits and owner checks

- Preflight confirms availability/identity at that instant; disk/network/process state
  can change later. Existing runtime status/retry/error handling remains necessary.
- Windows is the exercised platform. POSIX ownership discovery remains conservative;
  unknown processes are not automatically terminated. No browser interaction or
  real terminal was claimed by the smoke; Vite and its API proxy were HTTP-checked.
- Client major versions must be >=16; a later incompatibility with the actual server
  still fails the dump/inspection gate before migration. Docker control-system
  identity access must be allowed; otherwise install native PostgreSQL clients.
- Normal startup still has its established automatic dependency installation and
  Docker recovery. This is not a fresh-machine installation/performance acceptance
  (M7-05 and later gates remain separate).
- A hard crash can retain private partial/runtime files; no generic cleanup is added.
  Existing startup recovery handles identifiable owned application processes only.
