## Behavior and files

- `backend/app/services/backups.py`: reusable configurable-root store. Database identity
  is hashed from host/port/database (never password or user); a real connection verifies
  current_database before pg_dump. PostgreSQL URLs only; query parameters rejected
  rather than silently changing connection target. Host tools preferred; existing
  guarded Docker fallback only for local compose port, never a remote dump fallback.
- Archive/manifest are written into a unique private staging directory. pg_restore
  reads the TOC and all data blocks without connecting to a restore target; SHA-256,
  file size and UTC timestamp enter a strict non-secret manifest. Both files are
  flushed/fsynced before atomic directory rename. Partial staging is not a backup.
- Exclusive per-target lock serializes dump/retention. Unique identifiers prevent
  same-time overwrites. Reject symlink/junction ancestors and archive files; ignore
  unrelated names. Damaged recognized archives or unexpected contents refuse retention.
- Retention is explicit after successful backup creation/verification, daily namespace
  only: union of latest representatives for 14 Brussels days, 8 ISO weeks, 6 calendar
  months, always retaining the latest verified success. No duplicated bucket files.
  Manual/pre-migration/other-target namespaces are excluded. No recursive deletion.
- `backend/app/tools/backup.py`: one-shot CLI, default manual, configurable `--root`,
  optional `--kind daily` followed by safe retention. Errors are sanitized Ukrainian
  console messages; subprocess stderr and credentials are never echoed.
- `backend/app/tools/migrate.py`: legacy rotation is now a compatibility no-op;
  pre-migration backups are never automatically pruned. Existing migration backup
  naming/flow otherwise retained; new verified-store format does not rewrite old dumps.
- Tests: `backend/tests/tools/test_backups.py`, `test_backup_cli.py`, updated
  `test_migrate.py`; README corrects pre-migration retention and unsafe restore example,
  documents one-shot command, crash lock handling and local-disk limitation.
- `docs/STATUS.md` and this report preserve progress/evidence. Approved M7 plan and
  DECISIONS were finalized separately in the preceding documentation merge.

## Review and limitations

PRD/general, Python, database and security checklists are self-reviewed by the sole
engineer under Borys's explicit override; no independent reviewer is claimed.
Check final diff for target isolation, shell-free subprocesses, secret handling,
atomic publication, retention boundaries and absence of product/trading changes.

The configured root must be private to the OS user. SHA-256 detects accidental
corruption, not malicious tampering by that same privileged user. Archive inspection
does not replace restore drills. No restore-to-dev command is provided. Directory
rename provides atomic visibility; sudden power loss/filesystem failure remains an
operational risk, and local copies do not protect against physical disk failure.
Interrupted locks require owner inspection (fail closed); no unsafe automatic unlock.
Legacy pre-migration archives remain in their original format; their automatic deletion
is disabled. Manual/pre-migration growth requires owner-managed space planning.
Retaining daily representatives does not create missing historical daily/week/month slots.
