# M5 live check - position-size calculator (M5-06)

Two kinds of evidence, never mixed:

- **[QA]**: proven by isolated synthetic QA (fixture MT5, SYNTHETIC values, AI off,
  own DB `trading_journal_qa_m5`). It proves the app does what the contract says with
  the data it is given. It does **not** prove FundedNext numbers.
- **[OWNER]**: only Borys can prove it, by reading the real MT5 terminal. This is the
  ROADMAP M5 acceptance criterion (4 calculations within one volume step).

## Safe start (QA app)

```powershell
Set-Location "D:\Trading Scripts\WEB_application"
python scripts\qa_live_check_m5.py --no-browser   # API + worker + UI on 8000 / 5173
python scripts\qa_live_check_m5.py --prepare-only # only create (if missing) + migrate the QA DB
python scripts\qa_live_check_m5.py --api-only     # API on 8010, NO worker ("worker stopped" check)
```

- Accepts only `postgresql+psycopg://…@127.0.0.1|localhost|::1/trading_journal_qa_m5`
  (no URL query/fragment); refuses the dev DB `trading_journal`, `_test` and older QA DBs.
- Refuses to start if ports 8000/5173 (or 8010 for `--api-only`) are busy, a launcher run
  is recorded or an orphan worker exists: `scripts/dev.py` would stop it, and the QA
  launcher never stops what it did not start. Stop the normal app with `stop.bat` first.
- Creates the DB with `CREATE DATABASE` only if it is missing; never drops/resets/deletes.
  Migrations go through `app.tools.migrate` (pre-migration `pg_dump` to `backups/`,
  first run: `backups/pre-migration-80ae699b47ce-20261110T074542Z.dump`).
- `config/` is copied unchanged to `%TEMP%\tj-qa-m5\config` (marker `.tj-qa-m5-copy`);
  data and logs in `%TEMP%\tj-qa-m5\data` / `logs`.
- `MT5_SOURCE=fixture:backend/tests/fixtures/mt5/calculator_qa.json`, `ANTHROPIC_API_KEY=""`.
- Stop: `stop.bat` (or `python scripts\dev.py --stop`). The QA DB is kept.

## Observations from QA (not fixed; for the orchestrator)

- LOW, cosmetic API: decimal strings have varying scale in one response
  (`risk_budget` "1000.00" / "500.000" / "1500", `actual_risk` "999.6000000000000000",
  `actual_risk_percent` "0.99960000000000"). Contract says full precision, UI rounds,
  so not a contract violation; worth confirming the UI shows 2 decimals everywhere.
- `balance_unavailable` cannot be produced in a live app with one synced account (see
  above); only unit/API tests cover it.
