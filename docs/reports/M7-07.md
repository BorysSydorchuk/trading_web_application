## Change boundaries and RED/GREEN

Production changes are limited to the new browser-boundary module, installation
in `create_app`, and Vite response headers. Existing TestClient constructors now
use an explicit loopback base URL instead of artificial `testserver`; no production
test bypass or permissive CORS was added. Existing `forbidden` UI text remains in
`frontend/src/i18n/uk.ts`. No money/R/Decimal code, schema, MT5 code, dependencies,
data transformation, scheduling, audit-cost calculations or UI functionality changed.

Initial RED: 23 backend failures / three existing safe cases PASS, frontend frame
test FAIL. Added malformed port-zero coverage before final GREEN. Final boundary
tests cover 27 cases: foreign Host/Origin, credentials/path/query/opaque origins,
duplicate headers, cross-site metadata, IPv4/localhost/IPv6, normal Vite/native
clients and response headers. Denials return a constant JSON envelope and never
reflect attacker-controlled credentials. Origin comparison is intentionally exact;
use the normal relative `/api` frontend proxy, not a cross-port browser API client.
