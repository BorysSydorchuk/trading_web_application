## How to run

1. Follow `README.md` (unchanged from M0) to set up.
2. For MT5, follow `docs/MT5_SETUP.md`:
   1. Copy the terminal from `C:\Program Files` to `D:\MT5\<account-name>\`.
   2. Start the copy with `/portable` and log in with the investor password.
   3. Set the terminal path in Settings → Рахунки.
   4. Add `MT5_PASSWORD_<login>=…` to `.env`.
3. Start with `start.bat` and stop with `stop.bat`.
4. Optional: compare trades with `make trade-check ACCOUNT="FN Stellar Lite 2-Step" N=5`.
5. Without a terminal: set `MT5_SOURCE=fixture:backend/tests/fixtures/mt5/basic_week.json` for the worker.

## Known issues

- **The 2-minute target holds only inside trading hours** (Mon–Fri 08:00–16:00 Brussels per `rules.yaml`). Outside them the account syncs every 15 min, as designed.
- **Risk near breakeven:** when the move to exit is under 10 % of the entry-to-SL distance, risk falls back to `tick_value` from the current symbol spec. That value can differ slightly from the rate at the time of the trade.
- **Netting accounts:** position reversals (`inout`) are skipped with a visible warning. FundedNext accounts use hedging, so this doesn't apply (BACKLOG).
- **The terminal path in Settings is checked only by file name** (`terminal64.exe`), not against the portable folder. If someone enters the installed terminal in `C:\Program Files`, the app would use it. `MT5_SETUP.md` now warns about this in step 1.
- **After an MT5 call times out**, the account fails fast until the next connect. This has not happened live yet.
- **Not yet confirmed live:** which error code a closed terminal returns, and whether `initialize()` attaches to an already open portable terminal. The live check showed the error and the recovery work, but these details were not recorded.
- There are still no frontend unit tests (BACKLOG).

## Assumptions made (all in docs/DECISIONS.md)

- **Broker time:** history uses the `ny_close` rule; the offset from a tick must agree with the rule, otherwise the detected offset is used and a warning is logged.
- **Risk** = |gross P&L| × |entry − SL| / |exit − entry|, with the `tick_value` fallback described above.
- **R** = net P&L / risk. **Planned RR** = |TP − entry| / |entry − SL|, null without a TP.
- **Percentages** are relative to the balance at open.
- **Re-entry** = same account, symbol, direction, Brussels day and session, after a losing trade of the same idea.
- **Daily and weekly stops** are sticky within the Brussels day and the Mon–Sun week. Max trades per week flags the 11th trade and every one after it.
- **Initial SL source order:** deal, then order, then position, then user. An SL entered by the user is never overwritten.
- **Accounts:** only `active` accounts are synced and shown in the sync status (passed and failed accounts showed a misleading stale chip; fixed in M1-13a).
- **Sync state `stale`:** the latest attempt is older than 3 × the expected interval.
- **Warnings:** positions that can't be built are reported as an amber `warning`, not hidden.
