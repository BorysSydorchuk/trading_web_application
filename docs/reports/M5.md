## What was built

- **Pure sizing core** (`backend/app/domain/position_size.py`, M5-01/02): Decimal only, lot rounded **down** to the volume step, never rounded up to the minimum (refuses with `below_min_volume`), real risk ≤ budget, SL by price or points (broker `point`), TP for RR 1.5 / 2 / 3 rounded away from entry to the tick grid, bounded Decimal input. Stable error codes (`PositionSizeError`). 97 % coverage.
- **Broker data** (M5-03): `symbol_specs.point` and `tick_value_loss` captured from MT5 (never inferred). Margin requests table.
- **Schema clean-up** (M5-04b): dropped `calculator_margin_samples` and the `signature` columns (PM scope check).
- **API** (M5-04c/d, contract in docs/api.md "## M5"):
  - `GET /api/accounts/{id}/symbol-specs`, `POST /api/calculator/calculate` — answers from synced specs and the balance (reference balance, else synced; never starting balance). Never touches MT5.
  - Margin: `POST/GET /api/calculator/margin-requests`; worker job every 2 s does a read-only `order_calc_margin` on the account's terminal, sharing one MT5 source and lock with sync. 60 s expiry, stale/interrupted requests become failed. Offline: latest live margin for the same account/symbol/direction scaled to the volume, shown as a dated estimate; else «маржа недоступна» (never zero).
  - `order_calc_margin` added to the read-only allow-list (PRD 6.8); `order_send` / `order_check` / `order_calc_profit` stay forbidden by the guard test.
- **UI** (M5-05): «Калькулятор» page and a compact «Калькулятор позиції» panel on «Головна» (same component). Active accounts only, exact broker symbols, values sent as typed (comma accepted), all error codes in Ukrainian, live margin polling with estimate / unavailable fallback, stale results discarded.
- **QA tooling** (M5-06): `scripts/qa_live_check_m5.py` (isolated QA DB `trading_journal_qa_m5`, fixture MT5, AI off), synthetic fixture `calculator_qa.json`.

## How to run

- Normal app: `start.bat` (or `make dev`), menu «Калькулятор», or the panel on «Головна».
- Live margin needs the worker and the MT5 terminal of that account; without them sizing still works and margin shows the estimate or «маржа недоступна».
- Isolated QA: `python scripts\qa_live_check_m5.py` (see docs/reports/M5-live-check.md), stop with `stop.bat`.

## Known issues

- Margin de-dup is best-effort: two identical requests at the same instant can both run (one extra harmless lookup).
- The cached estimate scales the last live margin linearly; leverage / spec changes since then are not detected (the label shows its date and price).
- QA DB pre-migration dumps share the keep-10 backup rotation with the dev DB (BACKLOG).
