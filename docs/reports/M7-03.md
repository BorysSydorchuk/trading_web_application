## Audit and implementation

Existing `logging_setup.py` configured UTF-8 UTC console/file output and separate
`api.log` / `worker.log`, 5 * 1024 * 1024 threshold and five numeric archives. It
replaced its own handlers on repeated setup and kept HTTP/SDK loggers at INFO or above.
However, stdlib RotatingFileHandler only synchronizes threads using that handler;
separate processes could race on rename or keep stale open descriptors on Windows.
Its new-record size calculation also counted characters rather than UTF-8 bytes.

`app/log_rotation.py` adds a shared OS byte lock on Windows (flock on POSIX) around
each append/rollover. The permanent `<name>.log.lock` inode is never deleted. The
active log opens only inside the lock and closes before release. Three independent
processes can share the same name safely; API/worker continue using separate names.
There are no per-PID files and no generic directory cleanup.

Retention is **one active log plus five numeric archives**, each at most 5 MiB for
new writes: **30 MiB per name, 60 MiB for API and worker combined**, plus small lock
files. Other existing tools have independent log names and the same per-name bound.
A pre-existing oversized file is preserved and rotated on the next write; this task
does not rewrite old logs. Each formatted record is capped at 64 KiB UTF-8 plus an
explicit `[LOG TRUNCATED]` marker, keeping accidental giant tracebacks bounded.

`logging_setup.py` keeps idempotent handler installation, UTC timestamps and UTF-8.
Both installed output handlers use redaction after full message/traceback formatting:
configured database/API/Postgres secrets, MT5 password environment values, URL userinfo,
Bearer credentials and password/token/API-key assignments. Uvicorn's existing console
handlers receive the same formatter. Error type/context remains visible. Rotation/I/O
failure emits a fixed stderr message without the raw record or exception; console
output still carries the sanitized original event. External programs must close their
exclusive file handles before file output can recover; no foreign handle is killed.

`setup_logging` accepts plain `.log` basenames only, rejecting audit paths, traversal
and archive suffixes. `logs/ai_usage.jsonl` is neither read nor modified by rotation.
AI UsageLog, pricing, summaries, audio and backups have no implementation changes.
AI audit growth remains outside this task; any future retention redesign needs PM approval.

## Limits and owner checklist

All writers sharing a filename must use the new handler. External tools writing or
renaming the same file without the lock are outside this contract. Do not delete
`.log.lock` files while writers run. Locks release on process exit. Windows lock
acquisition uses the runtime's bounded retry; persistent contention or foreign sharing
denial can drop a file record with a visible stderr warning. Console logging remains.
The POSIX fallback is included but not exercised on this Windows machine.
Redaction covers known configured secrets and recognized credential syntax; arbitrary
unlabelled secrets must never be deliberately logged. Historical logs are not scrubbed.
No rotation/truncation of the real AI audit was performed, and real history was not
opened for these tests. Forced rollovers and locks used synthetic temporary logs only.

Normal Windows PowerShell, repository root; no AI/voice action is needed:

1. `[OWNER]` PowerShell → `$env:ANTHROPIC_API_KEY = ' '` → `.\start.bat` → «Головна»: звичні індикатори сервера та синхронізації працюють, нових помилок запису логів у вікні запуску немає.
2. `[OWNER]` Інше вікно PowerShell → `Get-Content -Encoding utf8 logs/api.log -Tail 10` та `Get-Content -Encoding utf8 logs/worker.log -Tail 10`: українські символи читаються, часові мітки мають UTC `Z`, помилки зберігають зрозумілий контекст; не надсилати необроблені логи із приватними даними.
3. `[OWNER]` PowerShell → `.\stop.bat` → у початковому вікні `.\start.bat` → «Головна»: сервер і синхронізація відновились; повторити читання хвоста двох логів — нові записи додано після попередніх. Для іншого LOG_DIR використати налаштований шлях.

Do not force rollover or file locks on real application logs. Synthetic tests above
cover those cases. Stop after local merge and await PM acceptance before M7-04.
