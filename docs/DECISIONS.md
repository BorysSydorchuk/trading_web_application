# Technical decisions

One line per decision: date, decision, reason. Product decisions live in PRD.md.

- 2026-10-31: Monorepo layout `backend/` (uv project, package `app`), `backend/app/worker/` for the worker, `frontend/`, `config/`, `scripts/`, `docker/`, `logs/`, `data/`. Reason: ROADMAP M0 allows `backend/worker`; one Python project means shared models and one venv.
- 2026-10-31: Local Postgres 16 via `docker-compose.yml` (service `db`, port 5432) as the default; a native install works by changing `DATABASE_URL`. Reason: no native Postgres on the dev laptop, Docker Desktop is installed; PRD 5 requires both to work.
- 2026-10-31: Test DB is a second database `trading_journal_test` in the same Postgres, created by `docker/postgres-init/`. Tests use `TEST_DATABASE_URL` and recreate the schema per session. Reason: simplest throwaway DB, no testcontainers dependency.
- 2026-10-31: Sync SQLAlchemy 2.x with `psycopg` (v3) driver, sync FastAPI endpoints. Reason: single local user, simpler code and tests than async; worker is a separate process anyway.
- 2026-10-31: API prefix `/api`, backend on 127.0.0.1:8000, Vite dev server on 127.0.0.1:5173 proxies `/api`. Reason: no CORS setup, localhost-only per PRD 3.
- 2026-10-31: Decimal values (money, prices, volumes) are serialized in JSON as strings; DB columns use `NUMERIC`. Reason: no float rounding in money math (backend-dev rule).
- 2026-10-31: Error responses use `{ "error": { "code", "message", "details" } }`; the frontend maps `code` to Ukrainian text in `uk.ts`, falling back to a generic message. Reason: UI text stays in one i18n file; backend logs stay English.
- 2026-10-31: npm (ships with Node) as the frontend package manager. Reason: nothing extra to install on a fresh clone.
- 2026-10-31: `make dev` and `start.bat` both call one Python launcher `scripts/dev.py` (starts DB if needed, runs migrations, starts API, worker, frontend, opens browser). Reason: one cross-shell implementation instead of duplicating logic in Makefile and batch.
- 2026-10-31: GNU make on Windows via `winget install ezwinports.make`; Makefile recipes use only commands valid in both cmd and sh. Reason: CLAUDE.md requires `make check`; Windows has no make by default.
- 2026-10-31: Frontend versions: React + Vite 8 + TypeScript 6 (strict + noUncheckedIndexedAccess), Tailwind 4 via @tailwindcss/vite, react-router 8, TanStack Query 5, ESLint 9 (eslint-plugin-react not yet on ESLint 10). Reason: current stable, plugin compatibility.
- 2026-10-31: `react/jsx-no-literals` is an ESLint error (props and a few symbols allowed). Reason: enforces "no hardcoded UI strings" from CLAUDE.md.
- 2026-10-31: Non-envelope HTTP errors (e.g. Vite proxy 502) map by status: 5xx → network_error, 404 → not_found, 422 → validation_error, else unknown. Reason: backend down shows "Сервер недоступний".
- 2026-10-31: Toasts dedupe by error code; queries opt out with `meta.silentError` (health poll uses it). Toasts are neutral-coloured; green/red reserved for P&L and deviations. Reason: PRD style rule, no toast spam.
- 2026-10-31: shadcn/ui components added by hand only when used (button, sonner); fixed dark theme, no next-themes. Reason: no unused code.
- 2026-10-31: Backend versions: FastAPI 0.162, Starlette 1.10, SQLAlchemy 2.1, psycopg 3.3, Alembic 1.20, APScheduler 3.11; build via hatchling, version from package metadata.
- 2026-10-31: Health: engine connect_timeout 2 s, `SET LOCAL statement_timeout=2000` in the health check; `db.error` is a fixed short English string by exception type, details only in logs. On Windows a refused port surfaces as a ~2 s timeout.
- 2026-10-31: Unhandled exceptions handled by a middleware (logs traceback once, returns internal_error); custom error codes via `ApiError(status, code, message, details)`.
- 2026-10-31: Logging: rotating 5 MB × 5 files, UTC ISO timestamps; `setup_logging(file_name)` shared by API (`api.log`) and worker (`worker.log`).
- 2026-10-31: Tests point DATABASE_URL at the test DB and LOG_DIR at a temp dir before importing the app; pytest treats warnings as errors (one Starlette TestClient deprecation ignored).
- 2026-10-31: Alembic migrations named `YYYYMMDD_<rev>_<slug>`; env.py honours an explicit `config.attributes["sqlalchemy.url"]` so migration tests can target the test DB.
- 2026-10-31: Schema numeric types: money NUMERIC(18,2), prices/volumes/tick values NUMERIC(20,8), percent/R NUMERIC(10,4); all datetimes TIMESTAMPTZ; system enums VARCHAR + CHECK; journal option fields VARCHAR(50) without CHECK (options live in YAML, old values survive).
- 2026-10-31: Accounts with trades cannot be deleted (FK RESTRICT), they are archived; symbol_specs and sync_log cascade with the account; trade/bias children cascade with their parent.
- 2026-10-31: Bias alignment stored as computed daily/weekly/monthly values plus `bias_alignment_override` + reason; effective value = override if set. Values: aligned/counter/neutral_bias/no_bias.
- 2026-10-31: trades.weekday (0 = Monday) and hour (0–23) are Brussels time of the open. bias_entries.period_date is a Brussels date (trading day; Monday for weekly; 1st for monthly). Digest periods are inclusive dates.
- 2026-10-31: `updated_at` bumped by the ORM (no DB trigger). Tests rebuild the test DB by dropping `public` and running Alembic `upgrade head`; a drift test fails if models and migrations diverge.
- 2026-10-31: Open positions are stored as trades with status `open` and close_time NULL (CHECK enforces the pair); the inbox only uses needs_sl/needs_description/draft. Default status for a closed trade is needs_description.
- 2026-10-31: accounts keep the last synced MT5 `balance`, `equity`, `balance_synced_at` (calculator offline, daily/weekly limits). trades.last_sl and trade_exit_deals.reason (MT5 DEAL_REASON, lowercase, no CHECK so unknown broker values never break sync) support breakeven detection.
- 2026-10-31: A custom test compares CHECK constraints between models and the migrated DB, because Alembic's comparison ignores them.
- 2026-10-31: Worker uses APScheduler BackgroundScheduler (UTC, coalesce, max_instances=1); main thread waits on a threading.Event in 1 s slices so Ctrl+C/SIGTERM/SIGBREAK stop it promptly on Windows; every job wrapped to log and swallow exceptions.
- 2026-10-31: Launcher (`scripts/dev.py`): children in their own process group, stopped with `taskkill /T /F` on Windows (no orphans); frontend starts in parallel with DB check + migrations; ports 8000/5173 fixed (match vite.config.ts); deps re-installed when lock/manifest is newer than a stamp file; port-busy check by exclusive bind; auto-starts Docker Desktop (wait ≤120 s) only for a local DB host; Node ≥ 20.19 (Vite 8); console messages English, UI Ukrainian.
- 2026-10-31: `scripts/` is linted/type-checked with the backend ruff/mypy config via explicit Makefile paths; `make test` runs `dev.py --ensure-db` first so `make check` works on a fresh clone.
- 2026-10-31: Extra schema columns beyond the M0 brief (accepted by PM): accounts unique `name` and unique (`login`,`server`), nullable `terminal_path`, `server_offset_detected_at`; trade_exit_deals.`account_id` (deal ticket unique per account); bias_entries `was_correct_source` (manual/auto) and `ai_filled_fields`; audio_notes `transcription_error`, `transcribed_at`, `duration_seconds` NUMERIC(10,3); digests `generated_at`; sync_log counters `deals_fetched`, `trades_created`, `trades_updated`, `open_positions`, `symbols_synced` (`ok` NULL while running, BIGINT id).
- 2026-11-01: MT5 investor passwords live in `.env` as `MT5_PASSWORD_<login>` (PM decision); `accounts.password_ref` is dropped. API exposes only `password_env_key` and `password_configured`.
- 2026-11-01: Broker server time: FundedNext runs on "New York close" time (UTC+2 winter, UTC+3 during US DST). Historical deal times are converted with this rule (`broker_time: ny_close` in config/rules.yaml); the offset detected from `symbol_info_tick().time` (rounded to whole hours, only trusted when within 2 min of a whole hour) must agree with the rule for "now", else the fixed detected offset is used and a warning logged. Reason: a single current offset mis-converts history across DST changes.
- 2026-11-01: Risk amount from initial SL uses the trade's own realised conversion: `risk = |gross_pnl| × |entry − SL| / |exit − entry|` (VWAP prices); if exit = entry, fall back to `|entry − SL| / tick_size × tick_value × volume` from symbol_specs. Reason: exact for GER40/XAUUSD in a USD account without historical FX rates.
- 2026-11-01: R multiple = net P&L / risk amount (commission and swap included); planned RR = |TP − entry| / |entry − SL| (null without TP); risk % and P&L % are relative to balance at open = current balance − Σ(profit + commission + swap + fee) of all deals at or after the open time.
- 2026-11-01: Re-entry = same account, symbol and direction, same Brussels day and session, opened after an earlier trade of that idea closed with net P&L < 0. "Idea" for max_reentries_per_idea = same account + symbol + direction + session + day.
- 2026-11-01: Daily/weekly stop violations flag entries made after the closed-trade P&L of the day/week (Brussels day; Mon–Sun week) crossed the limit, as % of the balance at the start of that day/week. Max-trades-per-week flags the 11th+ trade.
- 2026-11-01: Initial SL source order: opening deal `sl` → opening order `sl` → first SL seen on the open position by the worker → user input (`needs_sl`). Stored in `trades.initial_sl_source`.
- 2026-11-01: Rules engine recomputes `source=auto` violations on every trade update (idempotent); `source=user` violations are never touched by it.
- 2026-11-01: Launcher console messages are Ukrainian (PM asked for a Ukrainian Docker message; one language for the console). Code/log messages stay English.
- 2026-11-01: API decimal input accepts JSON strings or ints, rejects floats/bools/NaN; more decimals than the DB scale (money 2, pct 4) is a 422, not rounded; output at DB scale. Login must be a JSON integer. Unknown body fields are rejected (422). Currency must be 3 uppercase letters (UI uppercases).
- 2026-11-01: terminal_path is validated by file name only (`terminal64.exe`), not existence; the worker reports `terminal_not_found`. 409 conflicts detected from the unique constraint name (name → `name`, login+server → `login`).
- 2026-11-01: `mt5_password_for(login)` reads env (wins) then `.env` at call time (no cache, edits apply without restart); empty value = not configured.
- 2026-11-01: Broker time at a US DST switch (Sunday, market closed): repeated/skipped hour resolved with fold=0 (offset before the switch). No detected offset (stale weekend tick) → use the ny_close rule, marked unverified.
- 2026-11-01: MT5 `fee` is added into commission (no fee column). Close-by deals treated as normal exits. Unset SL/TP (0 in MT5) = null.
- 2026-11-01: TP source order: opening deal → opening order → open position → last TP on a deal. last_sl: open position SL → last SL on a deal → initial SL. Open trades carry realised P&L so far.
- 2026-11-01: Risk on a partially closed trade scales the realised P&L-per-lot to the full volume; SL equal to entry → risk 0, R and planned RR null. R and percentages are computed from the rounded 2 dp money values so stored numbers agree.
- 2026-11-01: Positions with incomplete deal history (exit without entry, over-close) are skipped with a reason; the sync fetches all deals of a position, not just the time window.
- 2026-11-01: Journal option values are stable snake_case keys (e.g. `ifvg_m5`, `qm_m5`, `fractal_update`, `point_b`, emotions `calm/confidence/fomo/fear/revenge/fatigue/boredom`); Ukrainian labels live in journal_fields.yaml. rules.yaml references option values (`qm_not_in_ny.entry_model: qm_m5`).
- 2026-11-01: Config files: strict validation (all rule keys present, quoted "HH:MM", non-overlapping sessions, duplicate YAML keys are errors, only true/false are booleans); cached and auto-reloaded on file change; broken config → ERROR log at startup and `500 config_error` from config endpoints, API keeps running. CONFIG_DIR env overrides `<repo>/config`.
- 2026-11-01: Settings UI: native `<select>`/checkbox (one new dep: @radix-ui/react-dialog); PATCH sends only changed fields; server field errors shown next to the field; login limited to JS safe integers.
- 2026-11-01: Positions with `inout` (netting reversal) deals are skipped with reason "netting reversal (inout) not supported" — FundedNext accounts are hedging. Risk uses the tick_value fallback when |exit − entry| < 10 % of |entry − SL| (realised P&L too rounded to be precise).
- 2026-11-01: Rules engine details: daily/weekly stop counts net P&L of the same account's trades closed strictly before the entry within the same Brussels day / Mon–Sun week; limits inclusive; no violation without balance_at_open. Max trades/week per account, ties ordered by key. Re-entry violation only on trades flagged is_reentry beyond the limit. Missing TP is not a min-RR violation in v1; min RR and max risk are strict comparisons. Entry-session violation only for "outside" or a configured session with entries_allowed=false (a session name missing from config is not flagged). Daily/weekly stops are sticky: once the running closed P&L of the period crossed a limit, all later entries in the period are flagged. Breakeven needs an initial SL more than 1 tick from entry. A user-recorded violation with the same rule_key wins over the auto one.
- 2026-11-01: Launcher run file `logs/dev-run.json` records launcher + children (PID, creation time, exact command line); a process is "ours" only if all three match (PID reuse safe). Previous launcher is asked to stop via a request file before any force-kill; leftovers stopped with `taskkill /T /F` before deps install. Fallback without run file: port holders / `-m app.worker` from this checkout's backend\.venv or frontend paths. Foreign port holders are named, never killed. Process data via stdlib ctypes (fast, no localised netstat parsing). start.bat/stop.bat switch the console to UTF-8.
- 2026-11-01: PATCH initial_sl: open trade → 409 `trade_open`; SL must be a positive decimal (≤ 8 dp), differ from entry and be on the losing side (below entry for buy, above for sell). Trades list: plain `from`/`to` dates are Brussels calendar days, datetimes inclusive; nulls sort last; archived accounts' trades still listed (inbox counts and sync status skip archived).
- 2026-11-01: Sync state `stale` = latest attempt older than 3 × max(expected interval now, at last attempt), regardless of its outcome (a hung worker shows stale); the latest error stays visible while stale.
- 2026-11-02: Journal UI: all view state in URL (filters, period preset, sort, page, open trade); periods resolved against today's Brussels date (Mon–Sun weeks; 30 days = today−29), sent as YYYY-MM-DD; default period "усе"; page size 50; column choice in localStorage. Decimal display string-based (prices trimmed ≥ 2 dp, money 2 dp grouped, %/R 2 dp, "+" on positive P&L/R). Unknown codes shown raw.
- 2026-11-02: Inbox UI: one request (needs_sl, needs_description, draft; ≤ 500, newest close first), grouped; inline initial-SL form mirrors backend validation on digit strings. Route-level lazy loading + vendor chunk groups (entry ≈ 40 kB).
- 2026-11-02: MT5 layer: raw sources return server epochs/MT5 codes; only `app/mt5/convert.py` converts to UTC (time_msc when present) and rounds prices/SL/TP to symbol digits; history window widened ±1 h for DST edges. Every MT5 call runs with a deadline in a daemon thread (reads 30 s); after a timeout the source fails fast until the next connect (to confirm in live check). Reads retried once on IPC errors; initialize not retried within a cycle. `connect` verifies login+server of the terminal (else login_failed). Read-only allow-list of MT5 functions enforced by tests; `symbol_select` allowed (Market Watch only). terminal_path may be the exe or its folder.
- 2026-11-02: MT5 fixtures (tests/fixtures/mt5) are generated by build_fixtures.py (test fails on drift); their README lists expected results and is QA ground truth. Recorder `python -m app.mt5.record` dumps a demo terminal's raw data without the password.
- 2026-11-02: Sync: a user-entered initial SL is never overwritten; otherwise builder result (deal → order → position) wins and a known SL is never cleared; position SL persisted with source `position`. P&L % and R stay null while a trade is open; risk, risk % and planned RR are filled. `accounts.server_offset_hours` = offset in use now; `server_offset_detected_at` only when a tick confirmed it.
- 2026-11-02: Rules recompute (`services/trade_rules.py`) covers the account's trades from the Brussels Monday of the earliest affected week; used by sync and by PATCH initial_sl (broken rules.yaml → SL saved, ERROR logged, violations catch up next sync).
- 2026-11-02: Worker `mt5_sync` job every 60 s; account due when time since last attempt ≥ interval (60/900 s) − 5 s; only status `active` accounts synced, sequentially, each isolated. Running sync_log rows left by a stopped worker are marked failed at worker start. `MT5_SOURCE=fixture:<path>` runs the worker on fixture data (demo/QA without a terminal).
- 2026-11-02: Positions the builder skips are surfaced, not just logged: sync_log ok=true with error_code `positions_skipped` and details; sync status state `warning` (amber chip). Broker offset detection is ignored outside trading time and uses the newest watch-symbol tick (stale weekend ticks fall back to the ny_close rule). Due-ness slack = half the job interval (30 s) so multi-account cycles don't drift past the 2-minute target.
- 2026-11-03: Sync status (`GET /api/sync/status`, status-bar chips) lists only `active` accounts, matching the worker, which syncs only `active` ones. Reason: passed/failed accounts otherwise show a permanent misleading "stale" chip (found in M1-13 QA).
- 2026-11-03 (PM, M1 review): M1 accepted. The 2-minute live check stays an open item in docs/reports/M1.md until Borys reports the time from the demo account; if it takes more than 2 min it becomes the first M2 bug ticket.
- 2026-11-03 (PM): Passed/failed/archived accounts get no status-bar chip and are not synced. Settings → Рахунки shows each account's status and lets the user change it (already present since M1-05: status column + status select in the edit dialog).
- 2026-11-03 (PM): Settings rejects a terminal path under `C:\Program Files` or `C:\Program Files (x86)`: case-insensitive, both slash styles, after expanding env vars such as `%ProgramFiles%`. The error message points to MT5_SETUP.md step 1. First task of M2, with tests.
- 2026-11-03 (PM): Git workflow: one branch per topic `m<N>/<topic>`; merge to main with `--no-ff` only after code-reviewer APPROVE and green `make check`; push main after every merge; never force-push main.
- 2026-11-03 (Borys): New backend dependency `anthropic` (official SDK) approved for M2 AI extraction. Default model `claude-opus-5-5` (ANTHROPIC_MODEL in .env overrides). Effort configurable via ANTHROPIC_EFFORT (default `medium`, the model default; thinking cannot be disabled on Opus 5.5); measure latency against the 30 s target in QA. Server-side refusal fallback (`fallbacks: "default"`) enabled; the served model from the response is what the usage log prices.
- 2026-11-03: AI extraction anti-invention: structured JSON output (`output_config.format` json_schema generated from journal_fields.yaml), every value paired with an `evidence` quote; the server drops values whose quote is not in the input text, invalid options, out-of-range ints, and text values with `?` not present in the evidence. No free-form message field, so the model cannot ask questions; missing fields are computed by the server.
